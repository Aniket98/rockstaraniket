### Talking about - The Central Inventory (oraInventory)

The directory which is called "oraInventory" stores an inventory of all Oracle software installed on the system.

Focus here.
The oraInventory is a "directory". Oracle refers to this directory itself as the Central Inventory.

This directory `oraInventory` contains files that make up that inventory, including an important file:
`ContentsXML/inventory.xml`

This file `inventory.xml' contains inventory data (such as registered Oracle Homes).

There are other files & directories as well that reside in the central inventory directory, as shown below:

``` bash
[dir] oraInventory
		|_ [dir] ContentsXML/ — stores core inventory metadata
		|		|_ [file] inventory.xml — registered Oracle Homes
		|		|_ [file] comps.xml — installed components
		|		|_ [file] libs.xml — library metadata
		|		|_ [file] oui-patch.xml — patch-related metadata
		|_ [dir] logs/ — installer and patch logs
		|_ [dir] backup/ — inventory backup information
		|_ [dir] oui/ — Oracle Universal Installer-related files
		|_ [file] orainstRoot.sh
		|_ [file] oraInst.loc
```

Some additional files may appear inside the oraInventory directory, only during certain operations and are transient in nature. Because they are created only when needed, they may not exist permanently inside the oraInventory directory.

For example, lock-related files may appear during software installation or patching to prevent multiple processes from updating the inventory simultaneously.

Now, we will examine each item in the Central Inventory directory and understand it in detail:
<br>

***
1) ContentsXML

***

ContentsXML is a directory inside the Central Inventory directory that stores core inventory metadata.

This is one of the most important directories inside oraInventory, because it contains XML files that describe:

* Which Oracle Homes are registered on the system
* Which Oracle components are installed
* Metadata related to patches
* Other information used by Oracle tools such as OUI and OPatch

Inventory information is stored in Extensible Markup Language (XML) format. The XML format enables easier diagnosis of problems and faster loading of data.

Some important files inside ContentsXML include:
		
``` bash
[dir] oraInventory
		|_ [dir] ContentsXML/ — stores core inventory metadata
		|		|_ [file] inventory.xml — registered Oracle Homes
		|		|_ [file] comps.xml — installed components
		|		|_ [file] libs.xml — library metadata
		|		|_ [file] oui-patch.xml — patch-related metadata
```

As we can see each file is having .xml extension.

##### inventory.xml

Before we move further, here are XML Syntax – Quick Guidelines:
|_ Helpful Link: [W3Schools - XML](https://www.w3schools.com/xml/xml_syntax.asp)

```
1. Must have ONE root element
   - All elements go inside a single parent

2. XML declaration (The XML prolog is optional. If it exists, it must come first in the document.)
   <?xml version="1.0" encoding="UTF-8"?>

   Note: The XML prolog does not have a closing tag! This is not an error. The prolog is not a part of the XML document.

3. Every tag must have a closing tag
   <tag>value</tag> OR <tag />

4. Tags are CASE-SENSITIVE
   <Name> is not equal to <name>

5. Proper nesting is required
   Correct: <a><b></b></a>
   Wrong: <a><b></a></b>

6. Attribute values must be quoted
   <tag attr="value">

7. Special characters must use entities
   < → &lt;
   > → &gt;
   & → &amp;
   ' → &apos;
   " → &quot;

8. Comments syntax
   <!-- comment -->

9. Whitespace is preserved
   (spaces are not ignored)

10. New lines stored as LF

		Windows applications store a new line as: carriage return and line feed (CR+LF).
		Unix and Mac OSX use LF.
		Old Mac systems use CR.
		XML stores a new line as LF.

11. XML documents that conform to the syntax rules above are said to be "Well Formed" XML documents.
```

Opening the `inventory.xml`, we see:

``` bash
oracle@10:/u01/app/oraInventory/ContentsXML> cat inventory.xml
<?xml version="1.0" standalone="yes" ?>
<!-- Copyright (c) 1999, 2026, Oracle and/or its affiliates.
All rights reserved. -->
<!-- Do not modify the contents of this file by hand. -->
<INVENTORY>
<VERSION_INFO>
   <SAVED_WITH>12.2.0.7.0</SAVED_WITH>
   <MINIMUM_VER>2.1.0.6.0</MINIMUM_VER>
</VERSION_INFO>
<HOME_LIST>
<HOME NAME="OraClient19Home1" LOC="/u01/app/oracle/product/19.0.0/client_1" TYPE="O" IDX="1"/>
<HOME NAME="OraDB19Home1" LOC="/u01/app/oracle/product/19.0.0/db_1" TYPE="O" IDX="2"/>
</HOME_LIST>
<COMPOSITEHOME_LIST>
</COMPOSITEHOME_LIST>
</INVENTORY>
oracle@10:/u01/app/oraInventory/ContentsXML>
```

The file begins with an XML Declaration (called XML prolog): `<?xml version="1.0" standalone="yes" ?>`

version="1.0" → Says the file follows XML version 1.0 rules.

standalone="yes/no" → In an XML prolog, the standalone attribute is an optional part of the XML declaration that tells the parser whether the document depends on external resources, such as an external Document Type Definition (DTD).

+ standalone="yes": Indicates the document is self-contained. The parser assumes all necessary declarations (like entities or attribute defaults) are contained within the internal subset of the document.
+ standalone="no": This is the default value. It indicates that the document may rely on information from an external source, such as an external DTD, to be processed correctly.

Then, we see the XML elements:

```
What is an XML Element?
An XML element is everything from (including) the element's start tag to (including) the element's end tag.
```

<INVENTORY>
Root element. Everything in this file sits inside it.
<VERSION_INFO>
Metadata about the inventory format itself.
<SAVED_WITH>
Version of Oracle tools (OUI) that last updated this inventory.
<MINIMUM_VER>
Minimum version of Oracle tools required to read/use this inventory.
<HOME_LIST>
Contains all registered Oracle Homes on the system.

<HOME ... />
Each entry represents one Oracle Home.

Attributes:

NAME → logical name of the Oracle Home
LOC → actual filesystem path (this is the real location)
TYPE → type of home (commonly O = Oracle Home)
IDX → internal index (unique ID inside inventory)
<COMPOSITEHOME_LIST>
Used for special/combined homes (rare in simple setups).

----------- Paras ----------------

Inventory information is stored in Extensible Markup Language (XML) format. The XML format enables easier diagnosis of problems and faster loading of data. Any secure information is not stored directly in the central inventory. As a result, during removal of some products, you may be prompted to enter the required credentials for validation.

Oracle recommends placing the central inventory on a local file system that is not shared by other systems, since the central inventory is a system-specific inventory of the installations on this system. It is strongly recommended that you place the central inventory on a local disk so that installations from other systems do not corrupt the inventory. You should not place the central inventory in any Oracle home, Domain home or Application home location.
