This official article might be old so they might have mentioned the way for the older times. But you can learn more in deep why and how it matters.

#prechecks
check if any tablespaces are present and if you need to move them as well

#stop service
net stop postgresql-x64-15

#robocopy (try to use robocopy instead of mnanual GUI copy paste)
robocopy "C:\Program Files\PostgreSQL\15\data" "D:\PostgreSQL\15\data" /E /COPYALL /R:1 /W:1
robocopy "C:\Users\CodeSpot\Downloads\postgres_new_loc\postgres\data" "C:\Users\CodeSpot\Downloads\postgres_new_loc\newnavelilocation\data" /E /COPYALL /R:1 /W:1

#at new copied location
check datadir location -> change to new location
similarly, check other parameters if any old location is being used

#set permissions (here is shown NT AUTHORITY user, check yours)
icacls "C:\Users\CodeSpot\Downloads\postgres_new_loc\newnavelilocation\data" /grant "NT AUTHORITY\NETWORK SERVICE":(OI)(CI)F /T

#check current config
sc qc postgresql-x64-15

#change only -D path (you must copy and edit binPath from previous qc output)
sc config postgresql-x64-15 binPath= "\"C:\Users\CodeSpot\Downloads\postgres_new_loc\postgres_bin\bin\pg_ctl.exe\" runservice -N \"postgresql-x64-15\" -D \"C:\Users\CodeSpot\Downloads\postgres_new_loc\newnavelilocation\data\" -w"

#start service
net start postgresql-x64-15

#verify
show data_directory;
select pg_is_in_recovery();
select count(*) from pg_database;
